# Small pilot checklist

Use this only for a few interface/usability pilots.

## Before each person

- Open a fresh private/incognito browser window or reload the page completely.
- Confirm the page starts at `Übung 1 / 3 · Practice`.
- Use the same computer, browser version and input device when possible.
- Assign an anonymous pilot label outside the page, for example `pilot-01`.
- Tell the participant that this is a workflow pilot and that the exported file contains path edits, timing and UI operations.

## Observe without coaching

- Can the participant understand all three in-canvas practice guides?
- Is the local magenta dashed target visible on every method canvas?
- Does the participant mistakenly edit more than one region?
- Are German and English labels understandable and unclipped?
- Can the participant distinguish anchor points from orange control points?
- Are pause, resume, finish and give-up actions understood?
- Does any task feel trivially short or impossible within 90 seconds?

Do not teach method-specific strategies during timed tasks. Record confusion as a UI issue rather than fixing the participant's edit.

## Result delivery

- At the end, choose `Teilen / Ergebnisse speichern · Share / Save results`.
- If the operating-system share dialog appears, send the JSON file to the study owner.
- Otherwise collect the downloaded `shape-edit-<session>-<timestamp>.json` file.
- Confirm the file opens as JSON and contains `study_session_id` plus 12 records.
- Keep the original file unchanged; make analysis copies separately.

## After each person

Record separately:

- anonymous pilot label and exported session ID;
- browser, operating system and pointer device;
- task where confusion occurred;
- exact visible wording or control involved;
- whether a technical failure interrupted timing;
- one short optional participant comment.

Do not pool these convenience pilots into formal paper statistics.
